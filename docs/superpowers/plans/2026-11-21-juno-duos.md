# Juno Duos Mode (2v2 Partnerships) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Juno lobbies gain a host-only single/duos switch; duos plays 2v2 with seating-order teams ([0,1] vs [2,3]), shared partner-hand visibility, and team victory crediting both winners.

**Architecture:** `JunoRooms` table options gain `mode: 'single'|'duo'` (default single, frozen into the round at start); the engine is unchanged except team derivation and a duo win-attribution path; projections expose `teams` + `partnerHand`; mixed/old cohorts downgrade to single exactly like the memory pattern.

**Tech Stack:** TypeScript strict, Fastify, Drizzle/SQLite (one nullable `team` column via `db:generate`), React 19, i18next.

**Spec:** User decisions 2026-11-21 (chat): teams by join order ([0,1] vs [2,3]); both winners earn winner XP (place 1, identical XP); a leaver becomes abandoned and the partner continues solo; duo tables hold at most 4; partner's cards are visible (view-only, no playing them); mode switch to duos with >4 seated is refused.

## Global Constraints

- TypeScript strict, no `any`; complete implementations only, no TODO/stubs.
- No new runtime dependencies.
- `docs/systems/juno.md` (+ `api.md` for the `options.mode`/`?duos=1` additions) updated in the same change.
- DB workflow: edit `packages/server/src/db/schema.ts` → `pnpm --filter @veyvox/server db:generate` → commit both; never hand-edit `drizzle/*.sql`.
- Web build fails on literal UI strings: user-facing copy only via catalogs (`en` + `pt-BR` new keys; other locales fall back to `en`).
- Asset work: none (no new art; team badges reuse existing avatar frames).
- Reduced motion: no new animation (team badges are static).

## Review Focus

- Switching to duos with 5–6 seated is refused without mutating the lobby; switching back to single always works — Task 2 pins both, plus `juno_table_full` on join beyond the mode cap.
- A mixed cohort (any seated human without duos support) starts a classic single round even with duos selected; an old client reading a duo round gets 409 `juno_update_required` — Task 2 pins the downgrade and the refusal.
- Partner A's private hand is byte-identical in B's `partnerHand` while every other hand stays hidden and masked/cursed projections keep working — Task 3 pins cross-player isolation.
- A leaver's cards return to the pile and the partner continues solo with no phantom turn; a team reduced to zero humans removes the table per existing rules — Task 1 pins departure order preservation.
- Empty hand ends the round immediately with both teammates credited place 1 and identical winner XP, and the stored/retried scoreboard agrees — Task 4 pins settlement, retry determinism and the persisted `team` column round-trip.

## Review Focus

- A 5th join to a 2-person duo lobby is refused without touching the table, and the join button already reads full — Task 1 pins `juno_table_full` + unchanged roster; Task 2 pins the label.
- An old client seated in a lobby switched to duos forces a single round at start, never a broken duo view — Task 1 pins the downgrade (mixed cohort starts single).
- A blind/cursed player still sees only opaque own slots while the partner hand stays readable — Task 3 pins masked-hand opacity alongside a visible partner strip.
- A rematch after a duo round returns to a fresh 1-person lobby that still remembers duos mode — Task 1 pins `options.mode` survival across rematch.
- A restarted server credits the same XP from the persisted `team` column without double counting — Task 4 pins settlement retry determinism including `team`.
